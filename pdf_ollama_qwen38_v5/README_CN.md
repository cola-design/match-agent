# V5：Ollama / TenGen-ZhiHan:F16 整页识图测试

这一版撤掉了安装失败的自定义PDF解析插件。只用你已有的 **PDF-to-Images 1.0.1**、Dify内置文字提取和 **Ollama / TenGen-ZhiHan:F16**。不需要上传TXT、在电脑拆图或另部署识图服务。

## 直接这样测试

1. 在Dify导入 `PDF电气识图_V5_Ollama_TenGen-ZhiHan_F16.yml`，新建对话。
2. 在「设置 → 模型供应商 → Ollama」确认 `TenGen-ZhiHan:F16` 的模型类型为Chat、Vision支持为“是”；上下文长度建议32768，最大输出上限至少4096。此处沿用你已经配置的Ollama地址，不需要把地址或密钥发到聊天。
3. 在流程的两个Ollama视觉节点检查选中的是 `TenGen-ZhiHan:F16`。节点已设置 `num_ctx=32768`、`num_predict=4096`、`format=json`、`think=false`。这些是请求参数；Dify模型登记的上下文长度也要一致，不能只修改其中一处。实际资源不足时需按部署容量调整，不代表本交付已做硬件实测。
4. 在预览开始表单上传完整电梯PDF，发送“开始识图”。无需安装之前的 `electrical-pdf-0.1.0.difypkg`，也不需要依赖它的旧V4流程。

如果Dify模型列表没有这个名称，先在已有Ollama供应商下添加这个确切模型名，不要改成基础模型仓库名。底层Qwen3.8具备视觉能力，但你本地打包的Ollama模型也必须包含可用的视觉组件；仅配置一个文本模型不能接收图片。

## 本版输出

- 一份统一的图面候选表：原文、中文含义、回路/相别、按标注解码的参数、独立参数关联及待核对项。
- `统一汇总整份识图结果`节点的`result_json`保存结构化结果。数据较大时，`result_json`明确指向`result_pages`，逐页完整详情保存在该数组中，全文保存在`source_text`。聊天最多展示前50项，不会删除其余结果。
- 数量保持未确认。它没有接产品数据库、报价、采购审批或DWG生成。
- 本次优先验证3.8模型能否读对图，不额外接Excel导出插件。候选表可复制，后续验收通过再接文件输出。

## 解决了什么、暂时缺少什么

- 整份PDF直接上传，已有插件按整页转图片，代码按图片文件名绑定页码，避免拿错页；图片直接交给视觉节点，不把单个File对象传给代码节点。
- 千问直接看当前整页。内置文字提取只辅助核对型号，不能把其他页的文字当作当前页的器件，也没有提供原生文字坐标。
- C16A、1P+N、30mA、电压比、容量和线缆规格分开解码。独立30mA保留为支路要求，原文MCB不擅自改成RCBO。ATS的II不能推定2P。L1/L2/L3不计作独立器件。
- 不做设计审查，不把看不清、漏识别或模型JSON问题写成客户设计问题单。
- Ollama关闭思考并请求JSON。若供应商仍返回完整的`<think>…</think>`前缀，可分离思考与正文；不修补未结束的JSON，失败会显式保留。
- **没有自定义解析插件后，本版不具备原生矢量坐标提取或自动局部放大。** 密集整页图、小字和扫描图仍可能看不全；换成27B模型也不能直接证明精准识别。
- 单次1份PDF、最多12页，每页最多40项候选和20项独立参数。超出、看不清或未读完必须标记未完整，不能用“运行成功”证明全图读懂。输出格式和图面实例数量都不等于采购数量或识别准确率。

## 验收重点

先用电梯图核对：3处MCCB图面位置是否分开；2#变压器220/36V与1000VA是否关联；8#支路MCB-C32A/4P旁的30mA是否保留；KM与时间控制器是否归属正确；柜号、相别、主备说明没有混入器件数量。不要提前把问题转成设计结论。

测试用本地受控回复检查代码和Ollama请求格式，没有连到你的Ollama服务，也没有把客户PDF发送到外部模型。因此本交付没有宣称3.8识图准确率已经实测通过。
