# 完整PDF识图 V4：安装与测试

这是一套配套文件，面向Dify 1.8.0。你只上传原始PDF，不用拆图、不用TXT、不用在电脑运行解析脚本。

## 你需要做的三步

1. 解压交付包，在Dify的「插件」→「安装插件」→「本地文件」安装 `electrical-pdf-0.1.0.difypkg`。插件名称为「电气PDF原文定位与自动放大」，无需API密钥。它是本次提供的自定义插件，不是声称已上架市场的插件。
2. 在工作室创建/导入应用，选择 `PDF电气图_完整PDF自动放大_V4_Dify导入.yml`。先装插件，再导入YML。插件与YML必须使用同一交付包，不要混用版本。
3. 打开流程，确认两个千问节点选择了工作区可用的 `qwen3-vl-plus`。在预览的开始表单上传完整电梯PDF，发送「开始识图」。无需把密钥发给任何人。

结果包括一份Excel和一份JSON。Excel「选型信息」是统一候选表，「全部原文」保留原文和页坐标，「识别状态」列出失败、未关联和分歧。聊天表只展示前30项，完整记录在附件中。

## 这个版本实际做什么

- 在Dify插件内提取原生PDF文字、坐标和初步矢量支路关联；保留型号、电流、极数、漏电参数、电压比、容量和线缆规格。
- 每页先生成包含全部内容的概览图，只去除空白纸边。小字或不确定器件触发内部放大；无须用户拆图。
- 整页和放大图共用原PDF的ID。千问仅辅助判断不确定器件类别，不生成长篇器件表、坐标或接线。
- 用同一份原文数据统一合并，不按放大图中的重复出现次数增加候选项。不把跨页重复视图直接加总为采购数量。
- 独立30mA作为支路选型要求保留，不擅自把图纸MCB改写成另一型号。变压器电压比与容量保留关联。KM位号保留为候选，仍需确认对应实体。
- 输出用于核对选型输入，不做设计审查、不编客户问题单、不访问产品库、不报价、不生成DWG。下一阶段再接产品匹配。

## 必须知道的使用边界

- 本版单份PDF最多12页、30MB，整页加放大图最多24张；文件上传仍受你们Dify全局限制约束。超过处理预算会说明原因并停止，不会只处理前面部分后声称完整。
- 原生文字与矢量优先。扫描PDF或文字已转曲而不能提取的页面，会明确标记需要OCR；本插件没有打包OCR模型，不能宣称这类页面已完整识别。
- 程序的支路关联目前主要面向水平单线图；其他图面保留全部原文，未确认的归属留空。通用型号规则不等于厂家订货参数，未标参数不补造。
- 数量尚未批准；位号、功能说明、型号文字出现次数都不能直接代替采购实体计数。
- 离线代码/协议测试通过不等于实际千问识图准确。仍须用你工作区模型，对照原图核验；结果文件中的准确率与采购批准标志保持false。

## 插件安装条件

插件运行在现有Dify插件运行环境，不需要另建PDF服务器，也不改现有产品同步/API服务。

这是未签名的自定义插件。如果Dify提示「签名验证失败/禁止未验证插件」，需要由Dify管理员决定是否允许安装自定义插件；YML不能改变该安装策略。不要因为这种报错去关闭防火墙或改业务服务。平台管理员可参考Dify官方自定义插件安装文档处理签名策略。本交付没有修改任何服务器配置。

首次安装由Dify插件环境安装Python依赖，需要能访问配置的Python包源；上传文件读取沿用Dify官方文件通道。如果报文件地址无效，应核对现有Dify文件访问配置，不替换域名或猜测内网主机。

PyMuPDF依赖采用AGPL-3.0或Artifex商业许可。项目自有代码采用MIT；企业闭源发布前需评估依赖许可，详见插件源码的 `THIRD_PARTY.md`。

## 如何验收这次电梯图

先检查原文是否完整，再核对图面参数和归属。重点包括变压器220/36V与1000VA、8#支路独立30mA、KM及时间控制标识、相同型号在不同位置的独立实例。不要把工程复核、数据库匹配或采购批准作为本次识图测试已完成的内容。

## 源码与本地开发测试

源码中不包含客户图纸、模型输出、账户、密钥或数据库URI。

安装开发依赖后运行：

```bash
python -m pip install -r plugin/requirements.txt PyYAML
python test_v4.py
python test_sdk.py
```

有私有电梯PDF时，可通过 `ELEVATOR_SAMPLE_PATH` 指定本地路径运行额外验收；文件不会上传。构建时使用官方Dify Plugin CLI，先运行 `python build_meta.py`，然后 `dify-plugin plugin package ./plugin -o electrical-pdf-0.1.0.difypkg`。把CLI路径放在本目录后运行 `python build_workflow.py`，将实际插件校验和写入YML依赖。
