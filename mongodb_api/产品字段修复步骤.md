# 本机产品字段修复：先预览，再处理

本次不部署服务器、不删除产品、不重新导入产品，也不修改价格。请先只完成第1—3步，把预览报告发回核对。

## 已确认的问题

你提供的 Navicat 统计显示：116,632条产品的 `category`、`standard_specs`、`source_attributes`、`quality_flags` 都是字符串。API示例中的 `provenance` 同样是JSON字符串。编码 `material_code` 是字符串，这是正确的，应保留。

修复目标：分类、标准规格、来源信息为对象；属性、质量标记为数组。同时修正标准规格的派生数字：如 `AC380V` 应解析为380，而 `AC230/400V` 保留原文、不生成一个错误的单值。原始规格文字不会改写。

修复工具只更新 products 的 category、standard_specs、source_attributes、quality_flags、provenance、item_id。保留物料编码、原始属性内容、source_status、data_status、publication_basis；不访问 prices。item_id 如被导成数字，则恢复为字符串，不猜测丢失的前导零。

## 1. 下载并复制工具

下载：<https://github.com/cola-design/match-agent/raw/refs/heads/main/mongodb_product_repair_bundle.zip>

解压后，将其中 `mongodb_api` 文件夹里的两个文件复制到你原来的API目录：

- `repair_products.py`
- `product_contract.py`

原API目录是之前能运行服务的目录，里面已有 `app.py`、`requirements.txt` 和 `.venv`。现在先不要覆盖 app.py。保留原来的 .venv 和环境配置。

## 2. 在原API目录打开一个新的 PowerShell

如果目录与之前一致，逐行执行：

```powershell
cd C:\Users\dongyuan1\Desktop\mongodb_api_server_bundle\mongodb_api
dir .\repair_products.py
dir .\product_contract.py
dir .\.venv\Scripts\python.exe
```

三项都应能找到文件。不要在 `C:\Users\dongyuan1` 目录直接运行。原API可以继续运行，预览不需要停它。

## 3. 运行只读预览

```powershell
.\.venv\Scripts\python.exe .\repair_products.py --prompt
```

出现提示后依次输入，每输入一项按一次回车：

| 提示 | 填写内容 |
|---|---|
| MongoDB host IP | MongoDB服务器完整内网IP，不是电脑API地址；不要带 mongodb:// 或端口 |
| MongoDB user | `match_agent_api`，也可直接回车使用默认值 |
| MongoDB password (hidden) | 此数据库用户的密码；不是API密钥，输入时不显示字符 |
| Authentication database | `admin`，也可直接回车 |

数据库默认 `match_agent`，端口默认27017。`--prompt` 保证重新输入连接信息，避免误用当前终端残留的 MONGODB_URI。

运行时会先显示 `Mode: read-only preview`，每扫描5,000条显示进度。它会读取全部产品，并生成本地文件，**不会向数据库写入**。无需把密码填进Dify。

如提示缺少 pymongo，仍在同一目录执行：

```powershell
.\.venv\Scripts\python.exe -m pip install -r .\requirements.txt
```

然后重新执行预览命令。

完成后，当前目录会出现 `products_repair_...` 文件夹，包含：

- `repair_report.json`：统计报告，可以发回核对。`scanned` 是扫描条数，`documents_to_change` 是待修复条数，`invalid_documents` 是无法自动修复的条数。
- `products_repair_plan.jsonl.gz`：字段修改前后内容，用于回滚。请留在本地，不需要上传；它不是全库备份。

**现在先发送 repair_report.json，到这里即可。** 若仍有116,632条产品，scanned应为116632；正常情况下invalid_documents应为0。实际结果以现场报告为准。

## 4. 核对报告后才执行修复

此步骤需要具有 products 更新权限的账号；只读 match_agent_api 不能执行修复。不需要删除或修改只读账号。使用你在Navicat中已有的、获授权的写入账号，在本机输入密码即可。

修复前保存现有数据库备份，避免同时运行产品同步任务。以下命令会重新扫描并保存本次字段回滚文件，然后才开始分批更新：

```powershell
.\.venv\Scripts\python.exe .\repair_products.py --prompt --apply
```

这次提示用户名时填写有更新权限的账号，其余输入方式相同。若发现损坏字段，会停止写入并在报告中列出问题。成功后报告中 `mode` 应为 `applied`，`verification` 正常应是空对象 `{}`。

更新使用原始字段值作并发保护；遇到写入失败或同期字段变更时会停止，但此前部分批次可能已完成。因此出现 STOPPED 后应保留本次文件夹，先核对报告与计划，不要删库或重复导入。

## 5. 在Navicat复核类型与条数

在 `match_agent` 数据库的新查询窗口执行以下只读统计：

```javascript
db.products.aggregate([
  {$group:{_id:{category:{$type:"$category"},standard_specs:{$type:"$standard_specs"},source_attributes:{$type:"$source_attributes"},quality_flags:{$type:"$quality_flags"}},records:{$sum:1}}},
  {$project:{_id:0,category_type:"$_id.category",specs_type:"$_id.standard_specs",attributes_type:"$_id.source_attributes",flags_type:"$_id.quality_flags",records:1}}
])
```

期望依次是 object、object、array、array。再查询状态统计，核对与修复前一致：

```javascript
db.products.aggregate([
  {$group:{_id:{data_status:"$data_status",source_status:"$source_status"},records:{$sum:1}}}
])
```

## 6. 再更新本机API

在原来运行API的窗口按 Ctrl+C 停止服务。在原API目录先备份旧代码：

```powershell
Copy-Item .\app.py .\app_before_product_repair.py
```

将修复包中的新版 `app.py` 复制到原API目录，覆盖旧 app.py。确保 `product_contract.py` 也在同一目录。数据库URI、数据库名和API密钥继续使用原来成功运行的配置；数据库修复时输入的写入账号不会改变API配置，API继续使用只读账号。

在原来已配置好环境变量的API窗口启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 0.0.0.0 --port 8000
```

通过原来的 `/docs` 页面验证 `/health`、按编码查询、产品搜索和查价。新版 `/openapi.json` 的版本为1.2.0；产品返回中的 category、standard_specs 应直接是对象，而不是带转义引号的字符串。

搜索兼容原来的 q 参数，也支持显式 model、category。指定型号必须匹配，规格得分在截取候选前排序；仍须由工作流校验工程参数和附件需求，不能把第一条当作定型结论。坏的结构字段返回明确503，不伪装成空结果。

以后只改 MongoDB 中的价格记录，不需要重启此API。接口每次读取当前数据库；真实价格应明确版本、有效期和依据，避免同一天存在多个冲突的ACTIVE价格。

## 如需回滚

使用**实际执行修复时**生成的文件夹中的计划，不要错用另一次预览计划。将下列路径改成实际路径，以有更新权限的账号运行：

```powershell
.\.venv\Scripts\python.exe .\repair_products.py --prompt --rollback ".\products_repair_实际时间\products_repair_plan.jsonl.gz"
```

只恢复计划中的字段；未执行或已经回滚的记录会跳过，后续又被人工更改的字段会触发冲突停止，不会强行覆盖。API旧代码可由 app_before_product_repair.py 恢复。
