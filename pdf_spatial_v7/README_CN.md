# PDF电气识图 V7：自动局部图与位置校验

## 你需要做什么

1. 在Dify插件市场安装 **Base64 / Base64 Codec**，作者 **bowenliang123**，插件ID为 `bowenliang123/base64_codec`。本YML锁定0.3.0版本，采用与Dify 1.8同期的SDK；请使用市场中的版本历史安装对应版本。它负责图片文件与编码之间的转换，不需要账号或API密钥。
2. 导入 `pdf_electrical_v7_spatial_crop.yml` 为**新应用**。沿用已经配置的通义千问 `qwen3-vl-plus` 和 PDF-to-Images（atoy0m0）插件。
3. 新建对话，上传完整PDF，发送“开始识图”。不需要手动拆图，不需要部署Python脚本或新增服务器。
4. 查看“按原页位置合并实例，校验回路归属”的输出。小结果在 `result_json`；完整分段结果在 `result_pages`，原始辅助文字在 `source_text`。

Base64插件市场地址：https://marketplace.dify.ai/plugin/bowenliang123/base64_codec

## 本次具体改了什么

每页保留整页概览，并实际裁切3个横向、3个纵向的重叠区域。裁切使用PNG像素处理，保留原始颜色、透明度和像素，不二值化、不生成新图像、不人为补画线路。局部图单独输入视觉模型，程序将局部坐标映射回原页。

- 同型号位于不同位置时分别保留。只有文字相同、位置相符、来自不同视图的观测才尝试合并；相邻同型号不按文字去重。
- 回路编号以图上实际可见标注为依据。模型要给编号位置和可见连线；程序检查几何关系，冲突时保留候选并取消自动归属，不按第几个器件补编号。
- 柜号、技术备注、负荷、相别和独立参数单列，不将柜号与备注计为产品。
- `1000VA`、`30mA`、`PC级`等单独记录并关联目标。目标缺失或冲突时保留参数，不猜订货型号。
- 图片文件的选择交给Dify原生列表节点；代码不接收迭代中的单个File。局部图文件名会再检查，局部图生成失败时不会拿整页图冒充局部图。
- 非法JSON、重复ID、缺失坐标和失败区域单独留痕。大图片编码按段传递，完整JSON按记录分段，避免截断后继续当作成功。

本版每页最多调用视觉模型7次。相比整页一次识别，处理时间和模型调用量会增加；是否读得更准必须用原图结果核对。

## 真实验证范围

已将用户提供的开发PDF以300DPI渲染，检查全部6个局部图与原图对应区域逐像素一致。已做重复实例、水平/垂直回路、不同子图、错误编号位置、参数分离、损坏JSON与图片传值等离线检查；也回放过上次的实际输出，保留原文且不补造缺失坐标。

运行过官方Dify 1.8的文件/Segment边界与列表选择方法，以及Base64 0.3.0插件原有编解码函数。测试使用本地执行后端与模拟SDK消息，没有完整部署用户的Dify，也没有从交付环境实际调用用户的千问API。上述验证不代表视觉识别准确率已经通过。

## 当前边界

裁切坐标和像素处理由程序确定；器件bbox、回路号和连线仍由模型读取。两个视图可能犯同一种错误，几何检查也无法证明所有连接关系正确。bbox不是PDF原生矢量文字坐标。本版未批准选型和采购数量，没有调用数据库、价格或CAD服务，也没有改数据更新程序。

每次支持1份PDF、最多12页。单页转图支持8位非隔行PNG，最大1600万像素；局部图编码最大96万字符。遇到预算超限会明确报告该区域失败，不删去后半页伪称完整。大幅图纸可在流程中的PDF转图节点降低DPI后重试，实际清晰度需另行核对。

## 开发复现

`python build.py`生成YML。`python test_v7.py`检查规则。集成验证通过 `DIFY18_CONTRACT`、`DIFY18_LIST_OPERATOR`、`BASE64_PACKAGE`、`PNG_FIXTURE` 指定官方Dify类型测试环境、列表节点源码、Base64插件包及本地图片路径。旧结果回放通过 `PRIVATE_LEGACY_RESULT` 指定私有文件。客户图纸、截图、原始模型输出和数据库凭据不在交付包中。

Base64工具参数schema摘自作者的Apache-2.0项目：https://github.com/bowenliang123/base64_codec 。流程中的PNG裁切和位置校验代码随本项目交付。
