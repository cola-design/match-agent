# 成套柜项目助手 V19 / Dify 1.8.0

本包提供可运行的项目后端、Dify Chatflow、签名Excel确认单和可选CAD转换服务。保留现有产品查询API与数据更新服务，两者不需要重新部署。项目后端只调用查询API，不连接或修改MongoDB。

**目前实现的是第一版闭环与接入代码，不代表已在你们的千问模型、Dify服务器和真实DWG转换器上验收。** 本地回归使用明确标注的模拟外部服务。真实图纸的识别精度、企业工艺模板与最终DWG必须在接入后验收。

## 一、流程

1. 上传客户图纸PDF，可同时上传技术协议PDF。缺少技术协议不会直接阻断；图纸中缺少的关键参数仍需问题确认。
2. PDF读取原生文字，渲染整页、裁切内容并放大分块，再交给千问视觉接口。扫描PDF也可以进入视觉识别，不要求一定有文字层。
3. 合并柜体/位号、检查证据与参数冲突、调用已有产品API预匹配。4P与3P+N、电流、脱扣曲线等沿用V18.2.1确定性规则。
4. 有问题时先给问题确认Excel；回传并解决后才出BOM确认Excel。信息完整时直接进入BOM确认。空识别结果不能当成“无问题”。
5. 回传已逐项确认BOM后生成采购清单、排产技术DOCX；价格/报价设置已确认才生成报价，工程参数与转换器已就绪才生成DWG。缺项时明确显示哪个输出受阻。

Excel黄色单元格可编辑。工程师必须填写确认人和逐项“是”。跨项目、旧版本、篡改固定字段的确认表会被拒绝。价格仅从API读取为参考，不能自动当成已审批采购价。BOM确认时如更改物料编码或单柜数量，会重新校验并要求确认新版BOM。

柜体数量/尺寸可在“柜体修订”黄色格纠正；单位、供货范围、柜号、型号和参数在“其他元件修订”中纠正。这类修订会触发重新检查并产生新版BOM，旧表不会被直接作为最终交付依据；只在“修改意见”写一句话不会自动修改这些字段。

问题阶段如需要同时改正图纸型号与参数，可在问题确认单J列填写关联元件修订JSON，例如`{"shown_model":"工程师确认的新型号","model_family":"明确系列","requirements":{"rated_current_a":16,"pole_count":"1P","trip_curve":"C"}}`，填写具体答复并确认后仍会重新查产品。此例仅说明格式，不是实际选型建议。

采购与报价只计入`OUR_PURCHASE`。`CUSTOMER_SUPPLIED`甲供、`UTILITY_SUPPLIED`供电局安装、`RESERVED`仅预留单独列示。数量=单柜数量×柜体数量；柜体数量必须为整数。

## 二、服务器部署项目后端

使用Python 3.10以上；本包在Python 3.12下执行本地测试。建议师兄在独立环境部署，项目端口默认9910。现有产品API仍使用原来的端口。

在**本README所在目录**执行：

```bash
python -m pip install -r requirements.txt
cp project_service/.env.example project_service/.env
python -c "import secrets; print('PROJECT_API_KEY='+secrets.token_urlsafe(32)); print('PROJECT_SIGNING_KEY='+secrets.token_urlsafe(48))"
nano project_service/.env
```

第一行安装依赖；第二行复制配置模板；第三行生成两串不同密钥，复制到刚生成的`.env`；第四行打开配置文件。不要使用示例测试密钥。

必须填写：

| 配置 | 填什么 |
|---|---|
| PROJECT_API_KEY | 刚生成的第一串密钥，随后也填到Dify |
| PROJECT_SIGNING_KEY | 第二串密钥，用于确认单签名；长期保存，随意更换会让已有表格与链接失效 |
| PROJECT_PUBLIC_BASE_URL | 用户浏览器能访问的项目服务地址，例如`http://你的服务器地址:9910` |
| PRODUCT_QUERY_API_BASE_URL | 已部署好的产品查询API根地址，不加`/v1/products` |
| PRODUCT_QUERY_API_KEY | 原产品API的访问密钥；不是MongoDB密码 |
| VISION_API_BASE_URL | 千问OpenAI兼容API根地址，通常包含`/v1`；不要填写到`/chat/completions` |
| VISION_API_KEY | 千问视觉API密钥 |
| VISION_MODEL | 你们实际有权限调用的视觉模型名称，必须支持图片输入 |
| CAD_CONVERT_URL / CAD_CONVERT_API_KEY | 可暂留空。接通转换服务后填写，详见CAD接口文档 |

默认报价加成率只是表格预填值，仍需工程师在回传表中确认。技术协议请转PDF；包含“技术协议”或“技术要求”的文件名会标记为协议资料，模型也会分析其他PDF中的约束。

`VISION_MAX_TOKENS`按实际视觉模型支持的最大输出长度设置，默认8192。输出被截断或结构错误会阻断本页，不会把半份识别结果当成完整BOM。

启动：

```bash
python -u -m project_service.app
```

该命令前台运行项目后端，`-u`及时输出日志。使用单个进程；不要启动多个Uvicorn worker，本版后台任务与项目锁位于进程内。长期进程管理、定时与反向代理由师兄按现有服务器方式配置，不需要Docker。进程意外退出时会保留项目文件，并在下次启动把未完成任务标记为中断，不会伪装成已完成。

`project_service/project_data`保存SQLite、上传PDF、识别图块、确认记录和输出文件。保留此目录和签名密钥才能继续原项目。单机版不支持多进程分布式队列，后续扩大并发需接队列与共享存储。

## 三、导入Dify 1.8.0

1. 创建新应用并导入`成套柜项目助手_V19_Dify1.8.0.yml`，保留旧应用用于对照。
2. 填写两个环境变量：`PROJECT_SERVICE_BASE_URL`（Dify容器可达的项目后端地址）和`PROJECT_SERVICE_API_KEY`（对应后端PROJECT_API_KEY）。本流程不直接配置千问；千问由后端调用。
3. 在聊天输入框上传PDF并发送`新建项目`。技术协议可一起上传；项目名称在开始表单填写。
4. 显示处理中时发送`查看项目`。不要再次发送新建，以免重复创建项目。
5. 下载问题确认Excel，填黄色格、确认人后，在**聊天输入框**上传回传表并发送`提交问题确认`。
6. 下载BOM确认Excel，逐项填写工程师确认“是”，在“报价设置”填确认人。“价格确认”填未税采购价、税率、依据并确认；“CAD工程参数”可由工程师填写JSON。
7. 在聊天输入框上传回传BOM并发送`提交BOM确认`。后端会生成当前能交付的文件，并列出报价或CAD缺项。补充价格/CAD后下载最新BOM表再次回传。

项目ID保存在当前Dify对话变量与后端数据库中。新对话继续旧项目，可在开始表单填项目ID；必须是同一Dify用户。开始表单的项目ID平时留空。多份项目请分别新建对话，避免混淆。聊天输入“重新识别”会重新处理已保存的PDF并废除旧的确认；更换图纸请新建项目。

本流程通过Dify 1.8.0 HTTP节点`form-data`上传本轮`sys.files`，传递文件本体，不要求后端访问Dify临时签名下载链接。不要手动设置Content-Type，客户端自动生成multipart边界。

若再次超时，先确认**Dify实际HTTP代理链路**能访问9910；宿主机本地curl成功不足以证明Dify可访问。只针对本服务开通必要的网络规则；本包不会自动改防火墙或其他服务配置。

## 四、部署后验收

```bash
curl --noproxy '*' --connect-timeout 5 --max-time 10 http://127.0.0.1:9910/live
python -m unittest discover -v
```

第一条应返回`{"status":"up"}`，只证明进程存活。第二条执行本地闭环回归，外部模型/产品/CAD使用受控测试替身，**不能替代真实业务验收**。依次在Dify测试：

- 上传实际项目PDF，核对所有柜号、单柜数量、柜体数量、型号、电流、极数、供货范围和关键技术备注；逐项对照原图，而不只看运行成功。
- 有疑问必须先出问题确认单；不完整表格、旧版本表格、其他项目表格均应阻断。
- 回传确认后总数量应正确，供电局/甲供/预留不得进入采购计价。
- BOM未确认时不能生成最终采购清单与报价。参考价格未确认时不得生成正式报价。
- 配好转换器后，使用实际CAD软件打开DWG；检查中文字体、单位、位号、布局、接线、版本及图框。只检测到DWG文件头不等于图纸合格。

## 五、CAD范围与尚需接入的部分

见[CAD接口与工程参数](docs/CAD接口与工程参数.md)。提供可运行的标准转换服务代码，但**没有捆绑CAD软件或ODA二进制**。目前自动绘图范围为依据工程师确认坐标/尺寸/端子/导线规格生成的元件布置和接线关系图；接线关系图使用节点示意，**不等于符合企业图例的完整电气原理图**。

要成为整套可直接排产的CAD，还需要企业图框、元件符号库、柜型结构规则、母排/开孔工艺、计算与审图规范。此包没有宣称从任意PDF直接还原全部工程设计。缺少转换器时不会把DXF改后缀冒充DWG。真实转换与最终工程出图验收仍待完成。

客户PDF、照片、历史报价和数据库凭据没有放进公开交付代码。项目服务生成的文件链接持有者可下载，请只在项目参与人中分享；配置TLS与访问范围按服务器现有制度执行。
