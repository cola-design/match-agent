# V6.1：修复类别/子图引用导致整页结果被丢弃

## 这次为什么是0项

用户提交的V6结果明确记录：第一遍器件提取和复看都在“候选类别或子图引用无效”校验失败。旧版会因任意一项类别不在词表、或其子图引用不在定义中，就把整页判为失败。原始模型回复已删除，失败摘要没有保存出错字段值，所以无法追溯本次具体是哪一项；不能断言一定是某个缩写或某个ID。

V6.1处理这个程序问题：保留能解码的条目，把未知类别和未确认归属逐项暴露，不靠任意给条目分配D1来通过检查。

## 使用

1. 解压，导入 `PDF电气识图_V6_1_校验兼容与结果保留.yml` 为新应用，新建对话。
2. 沿用已有的PDF-to-Images和Ollama模型 `TenGen-ZhiHan:F16`；无需安装解析插件或部署脚本。三个模型节点仍为同一模型，Vision支持为“是”，模型登记上下文32768、最大输出上限至少4096。
3. 上传原PDF，发送“开始识图”。若还有问题，提供“统一汇总中文解释与回路核对”节点的输出即可，结果中新增了关键诊断。

## 修复内容

- 常见类别别名、大小写及明确中文名称可规范化。优先解码原文MCB/MCCB/RCB等，不因模型返回RCB而把整页丢掉；没有依据的陌生类别仍为unknown。
- 数字ID转为对应数字字符串，纯大小写差异只在唯一匹配时处理。不会把“1”凭空改成“D1”，也不会把未知ID绑定到第一幅图。
- 子图引用无效的条目保留型号和解码参数，子图/回路归属为空并列待核对。其他有效条目继续处理。
- 条目ID缺失或重复时分配内部记录ID，不猜物理位置；引用重复原ID的回路暂不绑定。跨子图引用单独提示，不清空页面。
- 无法结构化的个别条目保留诊断记录，其他可读条目继续；非法JSON、截断、重复JSON字段等仍明确失败，不拼接残缺JSON假称成功。
- `diagnostics`保存类别原值、采用类别、子图引用原值、已定义ID及有限的回复片段。失败时保存解析位置附近信息；片段截取会明确标记，不宣称保存了全部原始回复。
- 失败页计入待核对，并列出辅助文字中尚未定位的原文。不会把它们冒充为视觉已识别的器件。

## 沿用V6的功能和边界

仍先建立回路表，再提取器件并做一致性检查。保留逐段中文解释、PC级、CAT线、线缆外层倍数、unknown和漏项提示。没有自动局部放大或原生矢量坐标；两个模型调用可能在同一位置误读。数量与选型未批准，没有调用产品库、价格或CAD服务，也没有更改服务器或数据库。

本版兼容处理验证使用受控字段变体、之前真实结果的开发回放以及本次失败摘要。由于原始模型回复已删除，没有对本次具体错误值做精确重放，也没有连接你们的Ollama做实测；代码检查通过不代表图纸识别准确率通过。

开发构建：`python build.py`。回归检查：`python test_v6.py`及`python test_retention.py`。私有样本通过环境变量提供，不包含在下载包或公开代码中。
