# V35：已有问题确认单直接开始选型

有已确认的清单，就可以从清单开始，不必重新上传图纸，也不必回到旧对话。

## 使用

导入 `downloads/cabinet_project_v35.yml`，填写原有产品 API 与 Dify 文件服务环境变量。新建对话，上传已有问题确认单 XLSX，点击“提交问题清单”或“开始选型”。也可在上方“项目资料”选择 XLSX 后点击开始选型。

- 型号、类别、单柜数量、柜体数量、单位、供货范围及问题确认信息完整：建立新项目并直接查询数据库，生成 BOM 选型确认表。
- 仍有缺项：生成“导入问题清单_待补充”，保留已有的型号、参数、数量、厂商选择和已填写的确认依据。补齐新表再提交，仍不需要 PDF。
- 有图纸时仍可上传 PDF 开始识图，两条路径由资料类型选择。

后续为：BOM 选型确认 → 采购报价确认 → 排产技术资料。清单入口不执行 PDF 转图和视觉模型。

## 接收的清单

1. 本助手导出的 SOURCE、SOURCEADD、PARAM、CAB、CHECK、SETTINGS 等可见工作表。
2. 通用 XLSX 明细，列名可用：型号或元件型号或产品型号、元件类别、单柜数量、单位、柜组、柜体数量。可补充指定厂商、供货范围、采购方式和电流、极数等中文参数列。

只有“数量”而没有单柜数量口径时，不自动猜测。缺少类别、实际数量、ATS 极数等信息时，会进入清单补充确认。

通用需求表未指定厂商时按“未指定”处理，未指定供货范围按我方采购需求处理；可以在清单中填写“甲供”或标准范围代码明确变更。通用表的主动提交被记录为用户提交需求，不冒充原工程审批。

## 新项目的数据处理

外部清单只导入可见需求和确认内容。新项目生成自己的项目标识和签名；不要求旧会话密钥，不把旧隐藏 META、已选产品、价格或报价审批当作新项目批准状态。

同一新项目的后续确认表，继续验证它自己的项目、版本、固定字段和签名。旧 BOM 或报价表不会被自动恢复成已批准订单。已有活动项目也不会被另一份外部表静默覆盖；另开对话导入即可。

带公式的输入明确拒绝，不使用缓存公式值；重复行ID、参数类别冲突和未确认问题继续检查。隐藏工作表不作为外部需求导入。外部文件被当成数据处理，不执行其中的指令。

可选技术协议原文件仍可保存；清单入口未自动提取其文字，影响选型的要求应已经包含在已确认清单内。

## 待审核产品查看

清单直入和产品审核范围是两件事。本版沿用已有产品 API 的查询与正式匹配规则。若现有接口只返回 ACTIVE，则待审核产品仍不会出现在响应里；查看它们需要现有 API 提供只读查询范围。不能靠改 YML 取回接口已经过滤的记录，也不应为了查看而修改产品审核状态。

## 本地验证

详见 `validation_v35.json`：

- 新对话通过聊天附件、上方项目资料两种方式上传清单，均能进入选型。
- 字段不全时保留内容并生成新确认表，补齐后能以新项目签名继续。
- 不继承旧隐藏签名、报价和审批；正常同项目回传仍验证签名。
- 清单直入完成 BOM、报价确认及排产表格流程。
- 原 PDF 入口完成原有业务链路；浏览器编辑页加载 155 个节点。
- 实际用户演示文件导入后形成 13 项查库请求，没有执行 PDF 或视觉节点。测试产品服务只有受控样例，不声称公司目录已匹配全部器件。

模型与产品服务是本地受控数据，公司模型、公司数据库和公司 API 调用为零。发布不包含客户 PDF/XLSX、原始回复、签名上下文、地址或密钥。

无需新增插件或另部署解析服务；沿用已安装的 Base64 1.1.0。选择 PDF 路径时沿用既有 PDF-to-Images 1.0.1 与 qwen3-vl-plus。
