# V31：原生文字定位、局部符号核实与定点补漏

导入 `cabinet_project_v31.yml` 后新建对话，上传完整 PDF，发送“开始选型”。沿用当前已成功调用的 qwen3-vl-plus、PDF-to-Images 1.0.1、Base64 1.1.0 和环境变量，不需要新增插件、外部识图 API 或另部署解析服务。

原 R2 表属于旧项目，不要回传到新对话。文件名中的 R2 是项目修订号，并非应用版本。

## 本次修改

- 在 Dify Python 代码节点中只读解析原 PDF 字节，提取原生文字、字体映射、文字矩阵和页旋转后的真实位置。复用已安装的 Base64 文件编码工具读取附件。
- 原生位置作为文字证据；视觉模型核实独立符号。文字出现次数不作为采购数量，图例与说明中的型号不自动变成采购实体。
- 以原生文字位置 ID 合并同一位置的跨图观测。同型号位于不同原生位置时分别保留，不再让整图模型重写全部清单或合并多处器件。
- 首轮未核实的型号、电压比等位置自动生成真实局部放大任务。电压比与旁边断路器分别核实，VA 容量只在目标唯一且位置相容时关联到已观察到的变压器。
- 使用印刷回路编号、导线端点和母线位置检查回路与负荷。支持横向、纵向及负荷在左侧的布局。没有充分位置依据的关联保留未确认；时控器、继电器位号不按最近一行强行归属。
- 保留柜号，柜号数量不等于柜体数量。无法核实符号的原生文字位置也会以明确标记的未确认候选显示，避免漏项只藏在日志里。
- 原生文字与视觉读法不同的情况单独提示，不静默覆盖原文或把模型没读懂写成客户设计问题。
- 新增“原图位置核对”和“回路与负荷核对”表，位置以页码、页面百分比表示，关联行号对应主清单。

## 完整业务仍保留

图纸及可选技术协议 → 识图/问题核对 → 数据库选型 → 选型确认 → 采购报价表 → 报价确认回传 → 排产技术资料表格。

保留六项入口：开始选型、提交问题清单、提交选型确认、提交报价表、查看项目、生成排产资料。此版未生成 DWG。

`DIFY_FILES_BASE_URL` 仍是插件可访问的 Dify 附件根地址；`MONGODB_API_BASE_URL` 仍是既有只读产品 API 根地址，不是 MongoDB 连接串。YML 不包含公司地址、数据库数据或密钥。

## 能力边界

原生读取器支持未加密 PDF 的常见页面树、压缩对象流、Flate/ASCII 过滤器、Identity-H 字体的 ToUnicode、常见拉丁字体、文字矩阵、页旋转和 Form XObject。它只解释 PDF 中的数据，不执行 PDF 脚本，也不访问网络。

扫描件没有原生文字；不支持的字体编码、加密和部分复杂 PDF 内容会明确降级为视觉候选，不能伪造原生位置。原生文字层本身也可能存在错误，最终需结合原图核对。

文字位置不等于电气拓扑，端点和母线规则也不代替电气设计审查。模型仍可能误判符号；型号、类别、数量、供货范围和关键参数必须人工确认后才进入选型。电缆标注不提供现场长度，程序不会编造长度或柜体数量。

此流程每批最多 12 页、100 项候选；定点补漏每页最多 24 处。超出预算会明确停止，不截断后续记录。原生解析失败会保留视觉识图路径，定位证据不充分时会要求复核。

## 本地验证

- 两份真实 PDF 的 95 段和 389 段文字位置分别与独立 PDF 库比较，包含全部首字符基线位置。
- 回归包含四种页旋转、中文 ToUnicode、压缩对象、Form、多页、横向/纵向/反向负荷布局、同型号多位置、跨视图重复、模型与原文冲突、合并标注、漏项复核、无原生文字降级和大结果分包。
- 官方 Dify 1.8.0 实际导入、浏览器编辑页、完整确认表回传及报价/排产流程验证。
- 实际 PDF 字节在 Dify 中解析并生成确认表；另用受控模型故意漏掉变压器，验证自动定点补漏；扫描版测试验证明确降级。

视觉节点和产品库联调用受控测试服务。没有调用真实千问，也未访问公司数据库。真实模型的符号识别效果仍须在公司 Dify 用同一份 PDF 验收，不能用本地流程通过代替识图准确率验收。

发布包仅含 YML、通用源码和汇总验证结果，不含客户 PDF、确认表、原始模型回复、签名上下文或测试凭证。
