# 成套柜项目助手 V28.1：Dify 1.8 本地验证版

直接导入 `cabinet_project_v28_1_dify18.yml`。本版在已交付 V28 上移除了出图相关功能，识图、选型、采购报价确认和排产表格按原业务顺序运行。使用者不需要部署压缩包里的 Python 后端；业务代码已经嵌入 Dify 流程。一个对话处理一个项目，表格必须在原对话回传。

## 先配置三项

1. 确认已有 **PDF-to-Images 1.0.1**，作者 `atoy0m0`。继续使用现有插件。
2. 安装 **Base64 Codec 0.3.0**，作者 `bowenliang123`。图片裁切、确认表读写和附件输出都使用它，不需要插件密钥。不需要之前安装失败的 PDF 解析插件，也不需要另装 Excel 生成插件。
3. 视觉节点选择公司已经能调用的 **qwen3-vl-plus**。正式 YML 使用 `langgenius/tongyi/tongyi`；保留公司已有的可用供应商配置，不要把模型密钥填到聊天里。

Base64 插件：[市场页面](https://marketplace.dify.ai/plugin/bowenliang123/base64_codec)。需要离线包时：[0.3.0 固定版本](https://github.com/svcvit/dify_plugin_collection/raw/59e0ed4ee7a36d8fe6b38e8e5651936799cab2b9/downloads/tool/bowenliang123_base64_codec_0.3.0.difypkg)。该文件 SHA256 为 `5d0ada53c34a556911068860add8e4c2023a633519887ad3c33641fb871c6d9e`。

在 Dify 流程“环境变量”填写：

| 变量 | 填写内容 |
| --- | --- |
| `MONGODB_API_BASE_URL` | 已部署的产品查询服务根地址，例如 `http://products.company.example:9000`。不包含 `/v1`、`/live` 或查询参数；不是 MongoDB 连接字符串，也不是 Dify 地址。 |
| `MONGODB_API_KEY` | 现有产品 API 密钥，使用 Secret 类型。 |
| `MATERIAL_MARKUP_RATE` | 参考销售价加成率，默认 `0.15`；只预填待确认报价。 |
| `QUOTE_DISCOUNT_RATE` | 参考折扣率，默认 `0`；仍需人工确认。 |

首次可先测试识图和问题清单；到数据库选型阶段才需要产品 API。产品查询不直接连接或写入 MongoDB，不调用产品数据更新程序。

## 如何使用

| 操作 | 要做什么 | 得到什么 |
| --- | --- | --- |
| **开始选型** | 填项目名，上传一份完整图纸 PDF；技术协议 PDF 可选。 | 自动转图、整页和六个重叠局部视图识别，输出识图与问题确认清单。 |
| **提交问题清单** | 对照原 PDF 填写黄色格，在聊天框上传 XLSX 后发送此命令。 | 校验项目、版本、固定列、数量、规格、供货范围与确认人，再只读查询产品库。 |
| **提交选型确认** | 核对产品和物料编码，上传选型确认表。 | 先完成产品选型确认，随后才读取 API 参考价格，输出采购报价确认表。 |
| **提交报价表** | 确认数量、未税采购价、销售价、税率、真实价格依据和整体结论，回传 XLSX。 | 复核产品资料版本，再输出已确认采购报价表和排产技术资料。 |
| **查看项目** | 随时发送。 | 查看当前阶段。 |
| **继续处理** | 接口恢复后重试，或重新获取当前确认表。 | 继续当前阶段，不丢弃项目。 |
| **修订资料** | 需要修改规格、编码、漏项或数量时使用。 | 重新打开识图确认表；旧选型、报价和工程参数失效，需重新确认。 |
| **保存项目资料** | 下载项目归档。 | JSON 状态、来源引用和确认记录；原附件由当前 Dify 实例保存。 |

采购清单与报价表合并处理。**报价表确认回传之前，不生成排产技术资料。** 供应商 API 返回的参考价不能直接变成已经批准的报价。

## 确认表填写

- 填写单柜数量和实际柜体数量；总数量按两者相乘。图中出现两个柜号，不自动推断为每柜两件。
- 物料编码列按文本保存，保留前导零。回传表直接按 XLSX 单元格解析，绕过 Dify 通用 Excel 提取的数字推断。
- 原图误识别行填 `EXCLUDE`，写明剔除依据并确认，不直接删除行。漏项在“手工补录”填写，当前每轮提供 5 个补录位；新增柜组可用 `NEWG1` 至 `NEWG3`。
- 无指定厂家时填“未指定”；有指定厂家时填厂家。替代需要明确同意，系统不默认替代。
- 供货范围为 `OUR_PURCHASE`、`CUSTOMER_SUPPLIED`、`UTILITY_SUPPLIED`、`RESERVED`。后三者保留在物料范围中，不计入我方采购报价。
- 非标项明确填写 `NON_CATALOG` 和非标依据；价格仍需人工确认。未找到唯一且参数匹配的标准产品时，返回核对，不以第一条检索结果代替。
- 技术协议原件和可提取文字保留；不能读出文字时会提示人工核对。**影响选型的技术要求必须写到对应元件的“确认技术参数JSON”**；“补充说明”只作资料保留，不自动改变选型。
- 不支持自动证明的技术参数会保留待核验，不能按已满足处理。图中不清楚、回路未绑定、局部识别失败等状态保留在“识图覆盖与待核对”中，须对照完整原件核对漏项。
- 填写实际数值，不使用公式；请勿改动固定列、行 ID 和“系统上下文”。不能混用别的项目或旧版本确认表。

目前报价汇总只包含已录入并确认的我方采购行；没有录入的柜体、辅材、人工、运费等不会自动计入，也不自动声称为全成本报价。

## 本版排产资料范围

现已输出：已确认采购报价表、柜体参数、已确认物料、技术资料原文和待填写的工艺复核记录。排产文件标明“待工艺复核”，不预填检验合格，也不代替企业已有的排产技术文件模板和审批。

按当前要求，本版已移除出图入口、工程参数确认分支、转换请求节点及 CAD 环境变量，先验证识图、选型和报价业务。

## 本次验证了什么

- 真实官方 **Dify API 1.8.0 + Web 1.8.0 + 插件守护服务 + 代码沙箱**，完成正式 YML 导入和编辑页测试；125 个节点正常呈现，无 React 页面异常，预览中输入字段和各阶段命令可见。
- 在真实 Dify 中实际上传合成 PDF、执行原作者 PDF 转图工具代码和 Base64 插件、下载和回传 XLSX，走完人工核对、选型、报价确认和排产资料下载。回传读取不依赖额外自建后端。
- 35 项业务回归测试；13 项真实 Dify 异常和恢复检查通过。包括固定列篡改、接口 404 后重试、未确认参考价拦截、已确认项目状态查看、归档、产品资料变更与重新修订。
- 测试报价：单柜 1 件 × 2 柜 × 未税销售单价 6 元 = 12 元；13% 税额 1.56 元；含税 13.56 元。

**外部依赖采用受控替身**：视觉模型返回合成固定结果，产品/价格来自本地合成 API。PDF 转图工具使用作者 1.0.1 的未改动实现，本地测试补齐了启动文件和图标；Base64 使用作者 0.3.0 原始包。没有调用真实千问，没有访问公司内网产品库，没有完成实际 DWG 转换。因此本地通过证明流程和文件协议可运行，不能证明客户图纸识别准确率或公司接口已联通。公司内网仍需用真实模型、现有产品 API 和客户原图验收。

本次测试的 Dify API 使用官方镜像导出的原始代码与依赖运行，Web、数据库、Redis 和沙箱使用本地容器；不涉及修改公司服务器。

## 当前容量

每项目一份完整图纸 PDF，1 至 12 页；识图候选最多 100 项。局部 PNG 超过 96 万字符传输预算、确认表/项目状态超出节点预算时明确停止，不把截断结果当完整清单。超过当前容量需按柜组分项目。输入 DWG 暂不支持，请先转 PDF。

这些限制是当前展示版边界，未覆盖无限页数、任意复杂图纸、正式企业审批和全套自动电气设计。

## 开发与复核

公开源码用于复核，不需要部署给最终使用者。安装 `pyyaml`、`openpyxl` 后可运行 `python -m unittest test_business -v` 和 `python build_full.py`。识图图结构继承 V7；业务阶段、确认表和产品 API 调用均在 YML 内。

Base64 工具参数 schema 来自作者 Apache-2.0 项目：[bowenliang123/base64_codec](https://github.com/bowenliang123/base64_codec)。公开交付包不包含客户原图、真实模型输出、账号密钥或本地联调环境。
