# PDF电气识图测试包 V3：先本机解析，再上传Dify

本包把 Python 工具和 YML 配成一套，用于先验证识图效果。Dify 使用你工作区已有的 `qwen3-vl-plus`。

**本轮不需要服务器解析接口、服务口令或额外模型密钥。** Python 在电脑上准备材料，然后通过 Dify 上传框提交。无需让服务器连接你的电脑，也无需新建Dify插件。

## 本轮流程

PDF → 本机原生文字/线条解析和高清切图 → 同批TXT及PNG上传Dify → 千问逐图识别 → 中文核对表、缺项、冲突及结构化结果。

模型结果仍需对照原图验收。本包不连接产品库、价格库，不生成批准BOM或DWG。

## 第一步：在Windows电脑准备材料

需要 Python 3.10 以上。解压本包，进入 `pdf_recognition_test_kit` 文件夹，把要测试的PDF复制到里面，命名为 `test.pdf`。源PDF不会被修改。

在文件夹地址栏输入 `powershell` 并回车。在打开的终端按顺序运行：

查看Python版本：

```powershell
python --version
```

创建本目录专用Python环境：

```powershell
python -m venv .venv
```

安装两个解析库，首次安装需要联网：

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

解析PDF、生成局部图片及配套说明：

```powershell
.\.venv\Scripts\python.exe -u prepare_test.py ".\test.pdf" --out ".\test_run_01"
```

终端显示“准备完成”后，打开 `test_run_01`。其中：

- `native_result`：本地解析Excel、JSON和带证据框的PDF。
- `batch_001`：第一批Dify测试材料，内有一个 `evidence.txt` 和最多4张PNG。
- `batch_002` 等：图纸较复杂时出现的后续批次。
- `test_index.json`：总批次及总分区统计。

再次处理时换一个新目录，例如 `--out ".\test_run_02"`。程序不会覆盖已有结果。

## 第二步：导入并设置Dify

1. 把本包里的 `pdf_recognition_test_v3.yml` 导入为新应用。
2. 两个视觉模型节点都选你已有且可调用的 `qwen3-vl-plus`。若工作区供应商接入不同，重新选择工作区已有模型即可。
3. 不用填解析服务地址、工具访问口令，也不用在聊天中提供模型密钥。
4. 新开对话，上方表单填写：
   - ①解析说明：选择 `batch_001/evidence.txt`，只选一个。
   - ②局部图片：选择同一个 `batch_001` 内的全部PNG，最多4张。
   - ③过载要求适用范围：仅按项目明确确认的要求选择，未明确则保持“未指定”。这不是所有项目的通用默认要求。
   - ④补充说明：只填已经确认的项目要求，可留空。
5. 发送“开始识图”。不要把ZIP或原PDF传到这些测试输入框。

如果有后续批次，每批新开一个对话，上传对应TXT和PNG。不要混批、改图片名或只选部分图片。

千问调用按原有模型账号计费。局部图数量较多或发生重试时，调用量增加。

## 第三步：核对测试结果

最终答复包含原图标注、中文含义、回路/相别、明确参数、识别缺项、模型分歧和工程待核对。局部连接候选保存在结构化结果中。

需要详细分析时，在本次运行的“汇总识图结果：核对表、缺项、冲突及结构化结果”节点，复制输出里的 `result_json`。这里不含模型请求头或密钥。

对照原图检查：

- 是否漏掉器件、变压器、电源、时控、接口或线缆标注。
- 字母和数字是否抄对；MCB/MCCB、16A/30mA、1P/1P+N等是否分清。
- 同型号不同位置是否被错误合并，跨视图是否被重复计算。
- 相别、回路、时控/接触器、交流输入/直流输出的归属是否正确。
- 模型是否补造未标注的极数、分断能力、数量、端子或厂家。
- 读取不清是否保留为识别缺项；工程问题是否有实际资料依据。

测试结论应按“漏项、误读、归属错误、连接错误、工程约束冲突”记录，不能用工作流全绿替代准确性验收。全部模型输出都保留 `engineering_verified=false`。

## 第四步：识图通过后再整合业务展示版

业务顺序为：客户资料/可选技术协议 → 识图 → 问题确认 → 数据库选型 → 采购及报价表 → 确认回传 → 排产技术资料与归档。

采购清单和报价表是同一份业务文档。报价表确认回传后才进入排产资料生成。完整业务YML需要在本轮识图验证后接入，本包不宣称已交付完整业务。

后续可将本地准备步骤自动接入解析服务，实现上传PDF后自动处理。直接DWG出图仍需CAD绘图/转换能力及工程规则，相关接口未接通时不能标为已完成。

## 验证情况与边界

本地检查使用真实生成的TXT/PNG和受控模型回复，验证编排、文件匹配、失败保留、重试、跨区冲突和作用范围；受控回复不是千问准确率。

**真实Dify工作区的导入、模型调用和识图准确性仍待实际运行。** 本次在Linux/Python3.12验证本地程序，Windows步骤调用相同Python入口，尚未在实际Windows电脑执行验收。

本包先用原生文字解析，默认不启用OCR。扫描件、转曲字体或文字不足会保留提示；不把这类页面说成已读全。图形、符号和连线仍由千问看局部图核对。完整逐端子网表、跨图实体统一、未知项目泛化和采购数量均未批准。

源文件最多200页、400个视觉分区。单批最多4张图；超过输出预算会明确停止，不能截断冒充完整。特别密集的图可以重新用 `--batch-size 1` 准备材料。

开发复现（用户不必执行）：

```text
python -m pip install -r requirements-dev.txt
python build_workflow.py
python -m unittest -q test_kit
```

验证详情见 `validation.json`。公开包只含通用代码、YML和说明，不含客户PDF、图片、报价或采购文件。
