# V6：中文解释、回路定位与漏项检查

本版只导入一个YML，沿用你已能运行的 **PDF-to-Images 1.0.1**、Dify内置文字提取和 **Ollama / TenGen-ZhiHan:F16**。不安装新的PDF解析插件，不增加独立后端，不修改产品同步、产品API或数据库。

## 使用三步

1. 在Dify 1.8.0导入 `PDF电气识图_V6_中文解释与回路核对.yml`，新建对话，不混用旧V5会话结果。
2. 确认三个Ollama视觉节点均选中 `TenGen-ZhiHan:F16`。模型登记的Vision支持为“是”、上下文长度32768、最大输出上限至少4096。节点已设置`num_ctx=32768`、`num_predict=4096`、`think=false`及JSON输出；沿用工作区已有模型地址，不需要发送密钥。
3. 在开始表单上传完整PDF，发送“开始识图”。可选填写已确认的选型要求，不填猜测。

每页先调用一次模型定位回路，再调用一次模型提取器件并核对；有可复看的问题时最多重看一次。因此比V5增加了回路定位调用，实际耗时取决于你们的Ollama服务。本交付没有做该服务的耗时或识图准确率实测。

## 改动

- **逐段中文解释。** MCB-C16A/1P会显示小型断路器、C型脱扣特性、16A、1极。BYJ按布电线说明，“2×4”解释为2根、每根4mm²；YJY按电力电缆导体规格说明，不把两者混为同一种电缆。
- **中文选型字段。** 单独列电流、极数标记、电压比、容量、剩余电流要求、ATS的PC/CB级、敷设标记、CAT通信线类别与外层线缆倍数。2×(...)不是批准采购数量。厂家型号仅解释有依据的部分，其他列待确认。
- **先读回路号再绑定。** 第一遍从当前图片读取编号、相别、负荷、器件和线缆的同支路关系。第二遍按成员ID归属，检查是否对应。不能按全文顺序或第几个器件补号，也没有把特定项目的编号统一加1。
- **保留柜号和子图范围。** 同页不同子图允许相同回路号，不相互覆盖。两柜共用一张图时，不直接按柜号个数乘采购数量。
- **检查原文提示漏项。** 提取文字中的器件/线缆/独立参数/编号与输出核对，漏出的CAT线、未关联PC级、unknown、两遍归属矛盾等列为待核对。全文顺序不代表位置，文字出现次数不代表实体数量。
- **失败不冒充完整。** 不根据模型自报“完整”直接通过。第二遍JSON失败会保留首轮可读内容；复看不能靠删除有原文支持的条目减少问题。替换未获全文支持的转写会留核对记录。
- **原值冲突不覆盖。** 独立30mA作为支路要求；不同参数标注冲突保留核对提示，不擅自选一个值。ATS的II不是2P，厂家未知性能不补造。

## 查看结果

聊天里先看“图面范围”“回路与负荷核对”，再看“标注含义与选型参数”和待核对列表。它们是识图核对信息，不是设计问题单。

完整结构化结果在 **统一汇总中文解释与回路核对** 节点：

- `result_json`：整份汇总、候选、回路、中文字段、待核对及原文提示。
- `result_pages`：大文件的逐页完整详情；若整份字符串超预算，`result_json`会明确指向这里，不截断冒充完整。
- `source_text`：完整的Dify内置辅助文字。

聊天最多展示前40项候选和前40条回路，完整详情仍在结构化输出中。没有接新的文件导出插件，本版以核对识图与选型输入为主。

## 验证与边界

已运行通用格式/语义规则测试，并把用户上次真实结果转换到新协议回放，检查能否暴露已有回路错位、漏项和参数缺口。其中回路归属的回放对照是按原图人工核对的开发参考，不是本环境新调用Ollama得到的第一遍定位结果。另用人工核对的正确归属检查规则是否误判。这是开发回归检查，不是盲测，不代表新版Ollama实际输出已修正。

仍然使用整页图像，**没有自动局部放大、原生矢量文字坐标或专业全拓扑恢复**。两遍都可能在相同位置误读；程序检查不能代替原图验收。`recognition_accuracy_verified`和`selection_approved`保持false。

本版单份PDF最多12页，每页最多40项候选、20条回路、24项独立参数、6个子图。超过预算必须说明或停止，不只保留前面内容假称完整。扫描页没有文字时，可以由视觉模型提取，但无法使用原文提示清单检查漏项。内置文字本身也可能漏字或打乱顺序。

当前没有做产品库匹配、价格计算、采购数量批准、设计审查或DWG生成。常见标注可明确解释，厂家型号的具体性能与供货拆分仍须产品资料；没有把某个测试项目的厂家型号固定当成某类产品。

## 本地开发

构建使用Python和PyYAML：`python build.py`。离线测试：`python test_v6.py`。私有回放需要设置`PRIVATE_RESULT_JSON`和`PRIVATE_NATIVE_JSON`，这些客户文件不随代码发布。

开源代码包含通用标注规则和流程配置，不包含客户PDF、DWG、识图输出、数据库URI或模型密钥。Dify实际图片请求仍由你工作区所选模型供应商处理。
