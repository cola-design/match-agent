# V32：按最终证据统一生成确认清单

导入 `cabinet_project_v32.yml` 后新建对话，沿用当前模型、插件和环境变量，上传完整 PDF，发送“开始选型”。旧对话的 R2 确认表不要回传到新项目。文件名中的 R2 是项目修订号，不是应用版本。

本版继续使用 qwen3-vl-plus、已安装的 Base64 1.1.0 和 PDF-to-Images 1.0.1，不需要新增插件、外部解析 API 或另部署服务器。保留原生 PDF 文字定位及定点放大补漏。

## 本次集中修复

此前视觉、原生位置和补漏结果虽然各自更新，交付表仍可能携带不适用的参数、非出线编号及首轮旧警告。本版在输出确认表前统一检查最终事实。

- 按器件类别约束参数：变压比和 VA 容量不能进入邻近断路器选型；PC/CB 类别只用于 ATS；剩余动作电流不能静默写入普通 MCB。源标记和被拒绝的关联仍保留证据。
- 时间控制器附近的 `t` 等功能标记转为注释，不单列采购器件。需要明确上下文；不会按一个字符全局删除真实设备。
- 相别、线缆片段、主用/备用等转入连接与来源标注，不混入出线回路号。支持数字编号及有原文证据的其他编号格式，不固定某张图的回路数量。
- 所有回路成员按最终器件重新生成，剔除无效关系；按实际印刷编号排序，不重编号码。
- 独立的 mA 标记按对应支路核对。若图面器件写 MCB，支路却另有 mA 标记，明确提出保护功能及类别核对，不擅自改成 RCBO，也不忽略标记。
- 已取得唯一、适用归属的容量等参数不再显示首轮“未关联”警告。器件类别未知、原文冲突、未完成覆盖等真实疑点继续保留。
- 线缆型号作为候选保留，不要求每条线缆注释都必须有一个独立元件符号或出线编号。供货范围、长度和实际用途仍需人工核对。
- 中文解释和选型参数由最终事实重新生成。新增“校验修正记录”和“连接与来源标注”，可追溯程序处理了什么。

器件、参数、回路和问题清单通过一致性检查后才交付表格；内部一致性检查失败时保留原项目，不输出可供误确认的新版表。

## 保留的业务

图纸与可选技术协议 → 识图/问题核对 → 数据库选型 → 选型确认 → 采购报价表 → 报价确认回传 → 排产技术资料表格。

保留六项入口：开始选型、提交问题清单、提交选型确认、提交报价表、查看项目、生成排产资料。DWG 出图仍未纳入本版。

`DIFY_FILES_BASE_URL` 继续使用插件可访问的 Dify 附件根地址；`MONGODB_API_BASE_URL` 是既有只读产品 API 根地址，不是 MongoDB 连接串。本文件不包含公司地址或凭证。

## 验证方式

- 保留原生读取、压缩 PDF、字体映射、多页、四种页旋转、横向/纵向/反向布局、定点补漏及扫描件降级回归。
- 新增故意含错的最终结果测试：错误参数归属、无效回路、失效成员、功能符号误建、旧警告、相邻支路残流标记、真实冲突保留，以及 CAT5/CAT5e 区分。
- 将实际上传确认表中的 32 项候选和对应原生文字位置回放，验证这批已知错误的处理，并经过导入 YML 内实际代码生成新的签名 XLSX。
- 在官方 Dify 1.8.0 中使用实际 PDF 字节及故意出错的模型测试回复，检查四类错误是否被拦截、表格是否生成和下载。
- 验证浏览器编辑页、确认表回传、选型、报价确认及排产表格；产品服务为受控只读测试数据。

本地模型为受控回复，未调用公司千问或公司数据库。真实清单回放证明已知错误的校验有效，不代表对所有图纸或真实模型的准确率保证。

## 能力边界

原生文字位置不等于独立器件、采购数量或完整电气拓扑。原生文字层也可能不完整或映射有错；不支持的字体编码、加密及扫描页面明确降级为视觉候选。仍需人工确认型号、器件类别、数量、柜体数量、供货范围与关键技术要求。

当前每批最多 12 页、100 项候选；定点补漏每页最多 24 处。超过预算明确停止，不截断后半份数据。需要复核的内容不会因为清理旧警告而自动获得审批。

发布内容仅含通用 YML、源码、测试和汇总验证；不含客户 PDF/XLSX、原始模型回复、签名上下文和测试凭证。
